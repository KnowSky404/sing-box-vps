# 服务端网络管理精简

[English](server-only-network.md)

状态：已实现，定向验收及证据边界见下文。本契约取代[统一规则与分流管理](unified-routing-management.zh-CN.md)中的客户端规则、广告、私网控制与安装默认行为。

## 1. 现状核实

基线为 `34c7140`。旧分流菜单同时管理服务端策略和客户端 LAN/CN 绕行、广告偏好；完整客户端配置导出还暴露在节点菜单、Agent 命令、状态和能力中。首次安装自动写入默认拒绝私网的路由策略，安装流程保存 WARP 设置，配置生成会创建 WARP 文件并可能注册账户。仅删除菜单不能解决这些耦合。

项目职责是管理 VPS 服务端。客户端交互仅限节点分享链接/二维码和 SubMan 同步；SubMan、节点连接材料及隔离协议探针所需的内部单节点 outbound 构造器继续使用，不生成完整客户端配置或设备分流规则。

## 2. 菜单方案

- **11 节点分享与订阅**：链接/二维码、SubMan、节点显示标签。
- **12 网络与分流**：Block CN、WARP（含节点出口与兼容的高级规则源）、AI/流媒体设置、出口与流媒体检测。
- **13 系统设置**：BBR、入站/出站协议栈。
- **14/15 脚本维护**：更新/卸载管理脚本。

网络策略保留三个领域：Block CN、WARP、AI/流媒体；预览/应用/恢复与检测是操作。删除广告、局域网控制、客户端绕行、完整客户端配置文件导出及 `sbv agent export-client --json`，同步清理能力与状态字段、过期测试。升级脚本不顺带删除已有导出文件。

媒体检测不注册 WARP、不改规则或节点凭据。WARP 检测只读取已准备的有效账户信息。编辑草稿后运行检测必须保留待应用选择；仅能在证明变化只来自检测缓存时刷新私有草稿指纹，原本已过期或存在无关并发修改的草稿仍按正常 CAS 拒绝应用。

## 3. 安装与节点独立性

首次安装只收集核心与节点连接参数。默认原生出口、Block CN 关闭、WARP 关闭，不注入广告或私网策略。单纯安装不创建策略文件、WARP 密钥/设置/域名/规则源或资产目录；普通节点、服务、证书和监听资源仍正常准备。

新节点继承当前服务端策略；编辑保留已有节点出口。新增/修改/移除可以更新已应用规则的受管 listener tag 范围，使原策略继续覆盖节点，但不改变策略选择、WARP 文件与账户、其他节点覆盖或手工 DNS/路由/出站。不隐式注册或修复 WARP；缺少必要账户资料时明确失败并回滚，由网络菜单显式修复。

## 4. 策略及优先级

精简格式为 `schema_version:2`，仅包含 `server` 下的 `block_cn`、`warp_ai`、`warp_streaming`、`rules`、`rule_sets`；完整 JSON 见英文版。后两个集合兼容已有显式服务端规则，放在 WARP 高级设置内，不单独扩大顶层菜单。保留严格字段、类型、长度、路径、归属与依赖校验，不写入客户端、广告或私网字段。

Block CN 默认关闭；开启时拒绝受管代理入口访问大陆域名与 IP，域名解析后也检查 IP。使用 `geosite-cn`/`geoip-cn` 二进制规则源并经原生出口下载，保持目标核心 HTTP client 兼容边界。顺序为必要处理/嗅探 → Block CN → 节点独立出口 → 显式规则/规则源 → AI/流媒体 WARP 预设 → 全局默认。因此固定原生/WARP 的节点也不能绕过 Block CN。这是目标分流，不是客户端来源封锁或整机路由接管。

WARP 支持原生默认、选择性和全量代理流量；原生默认不删除仍被节点或显式规则依赖的 WARP。节点出口为继承/原生/WARP。节点和全局策略经网络事务统一应用，不因此修改节点身份、凭据、监听或 SubMan 对象。

## 5. 旧版本与事务

v1 只读兼容；安装、编辑和删除节点保留其有效服务端行为。创建草稿时只在内存转为 v2，并提示待清理，即使未切换开关也能显式应用。应用只清理由可信生成基线和精确策略投影证明属于脚本的旧规则；实时配置缺失时，恢复仍从可信生成基线保留既有保护规则，不能因中性首次安装默认值将其清除。不按形状、协议或 tag 前缀接管手工内容。不能保持手工内容或顺序时拒绝应用并回滚。

打开、预览、取消、返回不写状态。应用继续使用锁、指纹、私有快照、候选校验、备份、原子发布、原活动服务仅重启一次、后检查、回滚和中断恢复。显式恢复同时还原策略和配置，可恢复 v1 快照。WARP 注册只属于显式网络操作；外部注册不可由文件回滚撤销，继续记录收据和证据边界。
