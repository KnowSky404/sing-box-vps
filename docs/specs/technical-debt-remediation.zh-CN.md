## 生命周期契约

卸载按准备/校验、停止服务及后检、受管资源清理、文件删除、最终检查执行。
变更前准备删除计划；停止失败或未确认停止时，不删除配置、核心、service、账本或恢复快照。
只有明确确认 unit 不存在且没有运行服务时，才允许按无服务处理。禁用失败不得被隐藏为成功。

实例防火墙使用现有事务原语，将受管监听目标转换为空。变更前校验账本，
保留无标记和无关规则；清理或补偿无法确认时保留日志。恢复文件不能证明完整回滚，
不能重启已经部分删除的安装；失败提示须说明可继续处理的最终状态。

菜单显示人类可读结果，正式和兼容 Agent 命令继续仅输出一个 JSON envelope。
两条路径均不能启动/重启无效配置，也不能绕过实例、组件或规则待恢复屏障。
现有 `service.start|stop|restart` 操作描述和手册同步反映共享行为。

既有 `core.uninstall`、`script.uninstall` 和旧协议批量删除继续登记为
`interactive_only`：它们尚无覆盖整个卸载的持久回滚日志及稳定结构化结果契约。
本轮加固已有业务函数和内部 purge 调用，不伪造无人值守契约或自动回答提示；
操作目录保留明确原因，由本地审查确认这一边界。

## SubMan 请求清理

凭证继续放在现有私有目录及 curl 配置中，不进入 argv 或常规日志。
请求边界捕获 INT/TERM/HUP，清理后恢复/传递调用方原有信号语义，
保留调用方读取的全局响应字段。写入后中断可能意味着远端结果不确定；
清理本地文件不代表远端回滚。SIGKILL/断电不在自动清理保证范围。
目的地、Gist、ETag 和读回协调校验保持有效。

## CI 范围契约

复用现有计划器和独立宿主测试校验，`--base` 保留其完整分支及工作区差异语义。
CI 检出受测 head 并获取足够历史；PR base / push-before revision 作为数据传入，
不得当作 shell 代码执行。

显式仓库范围绑定实际 merge-base。不得复用其他分支留下的未修改范围消除
`needs_scope`。PR 基线严格匹配；GitHub rebase 后受保护 main 的 push 允许已合并范围
引用 push-before 的祖先；并行 PR 已发布相同范围时也继续执行。PR/本地
模式仍拒绝未修改范围，非祖先及无效基线始终拒绝。只接受经计划器校验的 selector，
不执行任意命令或 shell 文本。
自动检查始终追加；缺失、过期或无效范围在测试前失败。
CI 直接复用宿主执行器；专用容器 fixture 使完整计划保持 `needs_scope`，
宿主检查可以独立通过，运行态要求记录 `required_not_run`，不得作为宿主执行。
选中的 Docker 场景同样记录未执行，绿色 CI 不表示运行态验收通过。

保留 `command-contract` job 名、只读 GitHub 权限及 `pull_request` 事件。
失败时也上传计划、逐项测试日志和耗时；普通改动不强制全套。
