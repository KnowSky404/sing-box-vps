# 统一规则与分流管理

[English](unified-routing-management.md)

## 入口与兼容

主菜单 13 统一管理服务端分流、广告拦截、私网访问控制、WARP 账户/规则源、受支持节点的独立出口，以及完整客户端导出偏好。菜单 1/2 只处理协议连接参数；交互新节点固定跟随全局，修改已有节点保留独立策略。Agent 完整记录中的显式策略保持。节点 ID、tag、凭据和既有实例格式不变；无法无损表达独立策略的 legacy 节点只读展示，不自动迁移。

缺少新策略文件时保留旧服务端生成路径。首次进入菜单只读推导实际私网拒绝和 WARP 状态，不把旧“高级路由”合并开关当成广告拦截。新安装默认原生出口、私网地址拒绝、广告关闭；客户端延续 LAN/CN 直连默认值。裸机在既有依赖准备之前不额外要求 jq；依赖与核心就绪后，在首次生成配置前写入默认策略。

## 策略与草稿

新增可选 `routing-policy.json` 放在私有项目目录内，仅兼容新增策略，不迁移既有协议或组件格式。字段结构见英文契约中的完整 JSON：服务端包含私网访问控制、广告开关、AI/流媒体开关、自定义规则及规则源；客户端包含 LAN/CN 直连与广告开关；共享广告配置包含 HTTPS 规则 URL、自定义域名后缀和例外。

自定义规则包含唯一 ID、匹配类型（精确域名/域名后缀/IP CIDR）、值、动作（原生/WARP/拒绝）及启停。规则源包含唯一标签、本地/远程、source/binary 格式、路径/URL、更新周期、动作及启停。所有输入是有界惰性 JSON，非法字段、类型、路径和重复项拒绝。广告 URL 可留空，仅使用内嵌域名后缀，便于自定义和隔离验收。白名单只排除广告拒绝，不强制原生出口，也不绕过私网控制。

全局 WARP 开关/模式与既有域名、规则源沿用原状态；节点覆盖仍写入各自实例记录。会话以私有临时草稿组合这些设置，编辑、取消和预览不注册账户、不写运行状态、不重启服务。应用前校验输入指纹，拒绝覆盖会话外的变更。

## 生效规则

显式保存策略后，受管代理节点先完成必要的域名嗅探和协议处理，再按私网控制、广告拦截、节点独立出口、自定义分流、AI/流媒体预设、默认出口处理。规则限于脚本管理的代理流量，不接管整台 VPS 的进程或手工入口。默认出口改原生不代表删除仍被节点/自定义规则使用的 WARP；概览须展示依赖。AI 与流媒体分别开关，已有自定义资产保留。

私网控制先通过 `local-dns` 解析域名目标，再匹配地址；DNS 答案中任一非公网地址都会拒绝，原域名仍供后续广告和域名规则匹配。关闭私网控制后，已启用的 CIDR 和可能含 IP 的规则源仍在首次 IP 匹配阶段解析目标，之前的域名规则优先级保持；IP 分流/拒绝不依赖私网开关。真实核心回归覆盖 localhost 和混合公网/私网答案，官方实现依据见英文契约。

继续执行既有配置归属与三方合并。新规则集必须精确匹配声明或受管生成对象，不能按宽泛前缀放行。手工配置和值/顺序保持；无法在保持手工顺序的同时证明新保护规则优先级时，拒绝应用并恢复，而不静默挪动手工规则。缺失、null、空 inbound 按核心语义视为全局匹配；反向和逻辑条件仅在正向条件确证不相交时才认作无关。范围判断与归属分离，归属仍要求精确生成对象；受管归属也不能让 route/direct/bypass 在保护前终结，相交组件规则拒绝而不挪动。空串、null、缺失的旧式动作均按核心语义分类为路由；广告白名单的入口限制放在逻辑 AND 内部，格式检查接受外层字段不代表实际限制。实例投影按可信状态认领精确绑定，不按 tag 与形状猜测；未知手工回退保留原位置或拒绝，已有绑定顺序和空库首节点优先级也必须证明；原生产器删除目标绑定前先做来源检查，不跨越保留的非终结前缀。类型化实例变更在同一受快照保护的事务中同步纯生成基线，使后续全局修改识别已提交的节点范围；纯生成事实可引用现场手工对象，基线同步仅临时合并完整 live 上下文校验并要求语义相等，最终仍只保存纯事实，不接管手工对象；旧 REALITY schema1 的迁移备份仅在可信规则事务中写入日志内，外部文件指纹保护不变，普通迁移继续原时间戳路径；预览显示只读旧节点，不触发迁移。接管只登记现场事实，不改配置或生成基线，随后显式应用规则才扩展到新接管的 tag，仍执行归属检查。

## 应用与恢复

应用要求已安装且有效的受管配置、独占管理锁和未变化的输入指纹。获取、复用或升级锁之后都再次检查规则恢复屏障，仅明确恢复路径可例外；拒绝时仅关闭本次新开的 FD，不关闭调用方已有锁。创建私有持久 `${SB_PROJECT_DIR}.rules-write.lock` 日志及项目完整快照，建立旧生成基线，暂存策略/资产/节点覆盖，复用依赖图、监听及真实核心检查生成完整候选。节点覆盖保留身份并使用既有类型校验和版本检查。

合并应用后只重启一次原本活动的服务；原本停止的服务保持停止。不重写 systemd unit 或防火墙。服务检查成功后才处理快照；错误及 INT/TERM/HUP 恢复目录与原服务状态，恢复不确定时保留日志并拦住其他写操作。菜单 13 在读取中断状态前提供恢复。上次成功事务的私有快照放在项目目录之外，避免递归备份；显式恢复时拒绝覆盖其后的无关配置修改。彻底卸载运行环境或明确删除项目配置时一并清理该私有历史；仅移除管理脚本并保留配置时继续保留。

已有策略后只修改客户端偏好，不重新生成或重启服务端。运行日志在恢复时单独保留；事务期间出现其他手工文件或 ACME 状态变化时，保留事务供核对，不自动覆盖这些变化。

WARP 注册仍按外部收据对账：已收到的结果保留到外层规则事务与服务检查成功提交后才清理；应用失败恢复旧密钥，同时保留结果供下次恢复，不再重复 POST；已提交事务恢复也可补齐收据清理。不能宣称文件回滚撤销了云端注册。进度、错误和预览不输出凭据或完整分享链接。

## 客户端导出

LAN、CN 直连和广告拦截独立设置。关闭 CN 同步移除 CN DNS/路由/规则集，保留解析代理服务器所需的引导 DNS；广告匹配先于 CN 直连。客户端只包含便携的远程或内嵌广告规则，不能引用 VPS 本地文件。沿用完整导出的核心检查、备份和原子发布。设置只影响重新导出的完整配置；普通 URI 和 SubMan 节点不分发设备路由规则。

## 验证边界

定向本地检查覆盖首次/追加/创建/编辑不再询问、旧覆盖保持、无 jq 边界、策略校验与优先级、精确归属和手工共存、WARP 依赖、取消/预览、一次应用、失败/信号恢复、中断写屏障及显式恢复。客户端八种开关组合和代表性服务端候选通过真实 sing-box 1.14.2 检查；可丢弃 Docker 的 TCP/UDP 流量验证过滤/出口及服务恢复，使用受控本地对端和内嵌广告规则，不使用真实 WARP 账户或生产凭据。

这是可界定调用方的共享路由兼容新增，不是核心或既有状态格式迁移；按 AGENTS.md 4.2 选测，并同步实际输入改变的场景夹具。mock、核心检查、Docker、真实外部服务、公网和生产证据分别记录。
