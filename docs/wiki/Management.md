# 交互管理

14 个结构化代理协议的新建和追加安装默认单个 `::` 双栈监听；Linux sing-box 的该 socket 同时接受 IPv4/IPv6，不需在同端口另加 `0.0.0.0`。修改已有实例时留空保留地址，显式输入和 Agent 完整记录中的地址仍优先；公网暴露确认保持原规则。REALITY 和 legacy 配置继续遵循全局入站模式，已有显式模式及单栈回退保持。ShadowTLS 内部 detour、客户端本地监听不受影响。完整范围见[默认监听契约](https://github.com/KnowSky404/sing-box-vps/blob/main/docs/specs/default-dual-stack-listeners.zh-CN.md)。

Mixed/SOCKS 分享链接对用户名、密码按字节执行 URI 百分号编码，避免 `@`、`#`、`%`、空格或换行改变链接结构；服务端凭据保持不变。HTTP Basic 无法表达含冒号的用户名或含 ASCII 控制字符的认证：此时 Mixed 的 Agent `links` 只提供 SOCKS5，并返回 `mixed_http_auth_unrepresentable`，不生成不可用的 HTTP 链接。SOCKS5 URI 不携带 UoT v2 等客户端选项，返回 `socks5_uri_transport_options_omitted`；需要完整配置时使用 `export-client` JSON。百分号编码不是加密，链接仍是敏感材料。

1. **安装新协议**：首次安装或向现有实例追加 VLESS（普通 VLESS 或 VLESS + REALITY）、Mixed、独立 SOCKS、独立 HTTP、Shadowsocks、Trojan、VMess、Hysteria2、Hysteria v1、AnyTLS、Snell、TUIC、NaiveProxy、ShadowTLS；协议安装主菜单第 1 项为 VLESS，进入后选择 VLESS + REALITY 或普通 VLESS；第 5 项为 SOCKS，第 6 项为 HTTP，第 9 项为 VMess，第 10 项为 Snell，第 11 项为 TUIC，第 12 项为 Hysteria v1，第 13 项为 NaiveProxy，第 14 项为 ShadowTLS。

## 统一规则与分流管理

安装节点时不再询问 WARP、广告/私网规则或独立出口。新安装默认原生出口、WARP 与广告关闭、服务端私网地址拒绝；新节点跟随全局，修改已有节点保留当前策略。旧安装首次进入规则菜单按实际配置读取，不自动启用新功能；原“广告拦截/局域网绕行”合并开关不能证明旧配置已安装广告规则。

菜单 13 按顺序提供：

1. 查看策略、受管规则顺序和作用范围。
2. 默认原生、选择性 WARP、全量 WARP及应用时重新注册账户。
3. 分别切换 AI 与流媒体预设。
4. 自定义精确域名、域名后缀和 IP CIDR 的原生/WARP/拒绝规则，支持添加、编辑、启停和删除。
5. 分别切换服务端与客户端广告拦截，设置 HTTPS 规则源、自定义域名后缀和广告例外；URL 输入 `-` 可清空并仅使用内嵌域名。
6. 切换服务端私网地址访问控制。
7. 修改受支持节点的独立出口。无法无损表达该设置的 legacy 节点只读展示，不自动迁移。
8. 分别切换客户端 LAN、国内直连与广告过滤。
9. 管理本地/远程规则源，以及查看和删除既有 WARP 域名、远程源条目；原本地 WARP 文件保持原路径，资产位置可查看。
10. 预览并确认应用，或显式恢复上次应用前的配置。

编辑、预览和取消只操作私有临时草稿，不注册账户、写入运行配置或重启服务。应用前检查会话外修改，生成完整配置并执行 `sing-box check`；合并服务端变更只重启一次原本活动的服务，原本停止的服务保持停止。已有策略后，纯客户端偏好修改不重启服务端。旧账户和规则资产保留；默认原生不代表关闭仍被节点或自定义规则使用的 WARP 出口。

服务端规则只作用于脚本管理的代理节点，按必要嗅探/解析、私网拒绝、广告拒绝、节点独立出口、自定义分流、预设和默认出口处理。启用私网控制时，域名目标先解析再判断，DNS 答案包含任何非公网地址都会拒绝。关闭私网控制不会停用自定义 IP 规则所需的域名解析。广告依赖可识别的域名；例外只排除广告拒绝，不强制直连或跳过私网控制。手工规则保留；无法证明其顺序与新过滤策略兼容时拒绝应用，不静默挪动。

客户端 LAN 直连是手机/电脑侧的导出规则，服务端私网拒绝是 VPS 侧的访问控制，两者分别管理。客户端偏好只影响重新导出的完整配置；普通分享链接和 SubMan 节点同步不把规则推送到设备。客户端规则不会引用 VPS 的本地文件。

应用失败或中断时恢复配置和原服务状态；日志保留。如果发现事务期间手工文件或 ACME 状态有并发变化，保留恢复材料并阻止其他写操作，不自动覆盖这些变化。检测到待恢复规则事务时先进入菜单 13；上次成功配置也可在此显式恢复，但会拒绝覆盖之后的其他修改。WARP 注册是外部操作，本地文件回滚不会撤销已发送的账户注册；收到的结果保留到规则及服务提交成功，失败重试复用收据，不重复注册。彻底卸载运行环境或删除项目配置也会删除私有规则历史备份；保留配置时继续保留。完整契约见[统一规则管理 SPEC](https://github.com/KnowSky404/sing-box-vps/blob/main/docs/specs/unified-routing-management.zh-CN.md)。

“当前已安装协议”只列出活动协议。删除最后一个实例后留下的空实例库用于保留 revision，不算已安装；再次安装会复用实例事务创建，保留原 revision 和手工配置。合法空配置不进入残缺实例接管；真正缺少组件、状态不一致或校验失败的安装仍受原检查保护。

删除最后一个实例后，菜单 2 仍会显示保留的协议，并标注“暂无实例，可重新创建”；选择后可沿用保留的版本记录创建新实例。

Hysteria2 新增协议和创建实例默认提供 ACME 自动签发，也可选择已有手动证书。`server_name / SNI` 必填，填写与证书匹配的域名（如 `hy2.example.com`），不带 URL 前缀或路径。HTTP-01 需要域名解析到 VPS 且公网 TCP 80 可用于验证和续期；Cloudflare DNS-01 需要 DNS 编辑权限，无需开放 TCP 80，邮箱可留空。手动模式填写证书与私钥的本机绝对路径，自签名证书选择“信任此证书”。新建实例默认监听单个 `::`，接受 IPv4/IPv6 连接；不要在同端口另加 `0.0.0.0` 监听。修改时留空保留原地址，首次安装的 legacy 配置仍按全局入站模式监听。HY2 服务端口需要允许 UDP，带宽、混淆与伪装网站均为可选项。

当脚本发现二进制、service、配置或协议状态层不完整时，会进入接管/修复流程，而不是把残缺实例直接当作全新安装覆盖。

## 长耗时操作与配置共存

实例变更会显示校验、备份、配置发布、资源同步及服务检查阶段；耗时操作每 5 秒显示已等待时间，完成或失败会显示结果。ACME 的域名验证和证书签发可能需要较长时间。进度写入 stderr，Agent stdout 仍保留 JSON，进度信息不包含 Token、命令参数或配置内容。公网 IP 探测有连接及总时限。

脚本可以与手工客户端配置共存。实例事务按原实例的 tag 更新入口，其他入口、出站、DNS、路由及顶层设置保留；手工组件不会仅因未登记到高级组件状态而被拒绝。完整候选仍需通过依赖图、监听资源和 `sing-box check`，已有协议索引时，Mixed/SOCKS/HTTP 按具体实例 tag 判断归属，同协议的未登记自定义 tag 也保留为手工配置；协议计数、状态校验及重建均排除这些手工入口，不隐式导入协议状态；默认保留 tag、已登记但状态缺失的入口仍执行完整性检查。未知入口类型或无法表示的同协议配置仍会停止操作并保留现场。

高级组件新增时按配置命名空间检查 tag：入口/出口/Endpoint 共用组件命名空间，HTTP Client、证书提供者、Service、网络命名空间和规则集各自独立；跨命名空间同名不会接管已有对象，同一命名空间的手工对象仍受保护。

防火墙同步只引用已登记协议/实例和启用的高级组件，不替手工入口、Endpoint 或 Service 放行端口。存在手工监听时，旧菜单也使用按地址及传输区分的防火墙事务，避免同端口不同地址之间的宽泛放行；现有手工防火墙策略不被接管。

全局重建在 `/root/sing-box-vps/managed-config.generated.json` 保存仅含脚本生成内容的私有基线（权限 600），将上一生成基线、当前配置和新生成内容合并。手工添加的对象和设置保留，基线中的受管对象可更新或删除；同一受管值同时被手工及脚本改成不同内容时报告归属冲突，不覆盖。旧安装首次生成按匹配的 tag 建立基线；手工删除的路由规则保持删除，省略的默认出口按现场首个出站保留其实际语义；legacy 删除操作先记录删除前的基线。legacy 整体移除若可能删除共享配置中的手工扩展，会取消并提示使用实例事务或先迁移扩展。不要手工编辑或删除基线文件，配置和基线均属于备份与回滚范围。

首次建立基线时，若现场受管节点的监听地址、端口、认证用户、密码、UUID、密钥、出口目标、TLS/传输安全选项或 ShadowTLS 严格模式/SNI 策略与状态文件不一致，会拒绝生成并保留现场配置，避免扩大监听或恢复已经撤销的凭据；可选显示名称及兼容默认值的补齐不会视为凭据变化。请先核对并通过接管/状态重建同步现场设置，再执行管理变更。旧安装修改 Warp、协议栈或新增协议前会先在事务中记录原生成基线，使明确要求的全局变更生效，并保留手工扩展；首次生成不会把尚未生成的字段误判为手工删除。

## 修改 SubMan 连接

主菜单 **11 → 4「设置或修改 SubMan 连接」** 可以重新设置部署地址、API Token、同步身份前缀和目标 Workspace Gist ID。部署地址可以是站点根地址，也兼容粘贴以 `/api` 或 `/api/nodes` 结尾的地址；脚本会规范化，避免重复拼接 API 路径。地址不接受账号、查询参数或 URL 片段。

地址未变时留空保留已有值，Token 隐藏输入。更换部署地址必须重新填写 Token 和目标 Gist ID，不会把保存的旧 Token 发给新地址。保存前只读请求目标，验证鉴权、Workspace 身份及 revision 等元数据；校验失败或输入中断时保留原设置。成功后原设置备份为 `subman.env.bak`，新旧文件均为权限 600。保存设置不推送或删除节点；随后可通过 **11 → 3** 同步。

同步身份前缀（保存字段仍为 `SUBMAN_NODE_PREFIX`）参与 `externalKey`，修改它会创建新的节点身份。切换地址、Workspace 或前缀不会删除原目标中的节点；需要清理时在原目标明确操作。目标校验、本地 API mock 和真实节点同步是独立验证。

## 实例名称与主机显示标签

主菜单 **11 → 5「设置新实例的主机显示标签」** 只设置后续新建实例的默认名称，不修改已有名称、不重启服务，也不推送 SubMan。默认名采用“主机标签-规范协议 ID-序号”，保存的实例名称作为分享和 SubMan 候选名称的基础；多用户、带宽和地址族按统一规则追加后缀。此标签与同步身份前缀独立。已有实例名称仍通过菜单 2 的对应实例管理修改；完整规则见 [实例与节点命名](https://github.com/KnowSky404/sing-box-vps/wiki/Node-Naming.zh-CN)（[English](https://github.com/KnowSky404/sing-box-vps/wiki/Node-Naming)）。
