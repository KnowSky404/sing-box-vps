# 交互管理


Mixed/SOCKS 分享链接对用户名、密码按字节执行 URI 百分号编码，避免 `@`、`#`、`%`、空格或换行改变链接结构；服务端凭据保持不变。HTTP Basic 无法表达含冒号的用户名或含 ASCII 控制字符的认证：此时 Mixed 的 Agent `links` 只提供 SOCKS5，并返回 `mixed_http_auth_unrepresentable`，不生成不可用的 HTTP 链接。SOCKS5 URI 不携带 UoT v2 等客户端选项，返回 `socks5_uri_transport_options_omitted`；需要完整配置时使用 `export-client` JSON。百分号编码不是加密，链接仍是敏感材料。

1. **安装新协议**：首次安装或向现有实例追加 VLESS REALITY、Mixed、独立 SOCKS、独立 HTTP、Shadowsocks、Trojan、VMess、Hysteria2、Hysteria v1、AnyTLS、Snell、TUIC、NaiveProxy、ShadowTLS；协议选择注册表第 5 项为 SOCKS，第 6 项为 HTTP，第 9 项为 VMess，第 11 项为 Snell，第 12 项为 TUIC，第 13 项为 Hysteria v1，第 14 项为 NaiveProxy，第 15 项为 ShadowTLS。
2. **修改已安装协议配置**：选择协议后进入对应实例管理，支持修改、设置默认实例等操作；legacy ACME/provider 保留原配置编辑流程。检测到未完成事务时，此入口直接进入恢复流程。
3. **移除已安装协议**：移除指定协议或 REALITY 实例；存在多个 REALITY 实例时会明确询问“单实例”或“整个 VLESS 协议”，并同步清理 QoS 与已移除端口的防火墙放行。
4. **更新 sing-box 版本**：保留配置的核心更新；目标 `sing-box check` 通过才重启。
5. **卸载 sing-box**：清理核心、服务与运行配置，保留管理命令 `sbv`。
6. **启动 sing-box**。
7. **停止 sing-box**。
8. **重启 sing-box**。
9. **运行状态摘要**。
10. **查看实时日志**。

12. **流媒体验证检测**：本机直出或 Warp 出口。

原“实例与状态”分组已合并到现有协议入口：菜单 1 安装、菜单 2 管理、菜单 3 移除，主菜单不再重复列出每种协议。协议安装列表按编号 1–15 排列，原有编号和留空选择行为保持不变。

删除最后一个实例后，菜单 2 仍会显示保留的协议，并标注“暂无实例，可重新创建”；选择后可沿用保留的版本记录创建新实例。

Hysteria2 新增协议和创建实例默认提供 ACME 自动签发，也可选择已有手动证书。`server_name / SNI` 必填，填写与证书匹配的域名（如 `hy2.example.com`），不带 URL 前缀或路径。HTTP-01 需要域名解析到 VPS 且公网 TCP 80 可用于验证和续期；Cloudflare DNS-01 需要 DNS 编辑权限，无需开放 TCP 80，邮箱可留空。手动模式填写证书与私钥的本机绝对路径，自签名证书选择“信任此证书”。新建实例默认监听 `0.0.0.0`，接受外部 IPv4 连接；修改时留空保留原地址。HY2 服务端口需要允许 UDP，带宽、混淆与伪装网站均为可选项。

当脚本发现二进制、service、配置或协议状态层不完整时，会进入接管/修复流程，而不是把残缺实例直接当作全新安装覆盖。

## 长耗时操作与配置共存

实例变更会显示校验、备份、配置发布、资源同步及服务检查阶段；耗时操作每 5 秒显示已等待时间，完成或失败会显示结果。ACME 的域名验证和证书签发可能需要较长时间。进度写入 stderr，Agent stdout 仍保留 JSON，进度信息不包含 Token、命令参数或配置内容。公网 IP 探测有连接及总时限。

脚本可以与手工客户端配置共存。实例事务按原实例的 tag 更新入口，其他入口、出站、DNS、路由及顶层设置保留；手工组件不会仅因未登记到高级组件状态而被拒绝。完整候选仍需通过依赖图、监听资源和 `sing-box check`，已有协议索引时，未登记且使用自定义 tag 的手工 Mixed/SOCKS/HTTP 客户端入口保留为手工配置，不隐式导入协议状态；默认保留 tag、已登记但状态缺失的入口仍执行完整性检查。未知入口类型或无法表示的同协议配置仍会停止操作并保留现场。

全局重建在 `/root/sing-box-vps/managed-config.generated.json` 保存仅含脚本生成内容的私有基线（权限 600），将上一生成基线、当前配置和新生成内容合并。手工添加的对象和设置保留，基线中的受管对象可更新或删除；同一受管值同时被手工及脚本改成不同内容时报告归属冲突，不覆盖。旧安装首次生成按匹配的 tag 建立基线；legacy 删除操作先记录删除前的基线。legacy 整体移除若可能删除共享配置中的手工扩展，会取消并提示使用实例事务或先迁移扩展。不要手工编辑或删除基线文件，配置和基线均属于备份与回滚范围。

首次建立基线时，若现场受管节点的监听地址、端口、认证用户、密码、UUID 或密钥与状态文件不一致，会拒绝生成并保留现场配置，避免扩大监听或恢复已经撤销的凭据；可选显示名称及兼容默认值的补齐不会视为凭据变化。请先核对并通过接管/状态重建同步现场设置，再执行管理变更。旧安装修改 Warp、协议栈或新增协议前会先在事务中记录原生成基线，使明确要求的全局变更生效，并保留手工扩展；首次生成不会把尚未生成的字段误判为手工删除。

## 修改 SubMan 连接

主菜单 **11 → 4「设置或修改 SubMan 连接」** 可以重新设置部署地址、API Token、节点前缀和目标 Workspace Gist ID。部署地址可以是站点根地址，也兼容粘贴以 `/api` 或 `/api/nodes` 结尾的地址；脚本会规范化，避免重复拼接 API 路径。地址不接受账号、查询参数或 URL 片段。

地址未变时留空保留已有值，Token 隐藏输入。更换部署地址必须重新填写 Token 和目标 Gist ID，不会把保存的旧 Token 发给新地址。保存前只读请求目标，验证鉴权、Workspace 身份及 revision 等元数据；校验失败或输入中断时保留原设置。成功后原设置备份为 `subman.env.bak`，新旧文件均为权限 600。保存设置不推送或删除节点；随后可通过 **11 → 3** 同步。

前缀参与 `externalKey`，修改它会创建新的节点身份。切换地址、Workspace 或前缀不会删除原目标中的节点；需要清理时在原目标明确操作。目标校验、本地 API mock 和真实节点同步是独立验证。
