# 交互管理

14 个结构化代理协议的新建和追加安装默认单个 `::` 双栈监听；Linux sing-box 的该 socket 同时接受 IPv4/IPv6，不需在同端口另加 `0.0.0.0`。修改已有实例时留空保留地址，显式输入和 Agent 完整记录中的地址仍优先；公网暴露确认保持原规则。REALITY 和 legacy 配置继续遵循全局入站模式，已有显式模式及单栈回退保持。ShadowTLS 内部 detour、客户端本地监听不受影响。完整范围见[默认监听契约](https://github.com/KnowSky404/sing-box-vps/blob/main/docs/specs/default-dual-stack-listeners.zh-CN.md)。

Mixed/SOCKS 分享链接对用户名、密码按字节执行 URI 百分号编码，避免 `@`、`#`、`%`、空格或换行改变链接结构；服务端凭据保持不变。HTTP Basic 无法表达含冒号的用户名或含 ASCII 控制字符的认证：此时 Mixed 的 Agent `links` 只提供 SOCKS5，并返回 `mixed_http_auth_unrepresentable`，不生成不可用的 HTTP 链接。SOCKS5 URI 不携带 UoT v2 等客户端选项，返回 `socks5_uri_transport_options_omitted`；需要额外 UoT 设置时按客户端能力手动配置。百分号编码不是加密，链接仍是敏感材料。

1. **安装新协议**：首次安装或向现有实例追加 VLESS（普通 VLESS 或 VLESS + REALITY）、Mixed、独立 SOCKS、独立 HTTP、Shadowsocks、Trojan、VMess、Hysteria2、Hysteria v1、AnyTLS、Snell、TUIC、NaiveProxy、ShadowTLS；协议安装主菜单第 1 项为 VLESS，进入后选择 VLESS + REALITY 或普通 VLESS；第 5 项为 SOCKS，第 6 项为 HTTP，第 9 项为 VMess，第 10 项为 Snell，第 11 项为 TUIC，第 12 项为 Hysteria v1，第 13 项为 NaiveProxy，第 14 项为 ShadowTLS。

3. **移除已安装协议**：移除指定协议或 REALITY 实例；存在多个 REALITY 实例时会明确询问“单实例”或“整个 VLESS 协议”，并同步清理 QoS 与已移除端口的防火墙放行。
4. **更新 sing-box 版本**：保留配置的核心更新；目标 `sing-box check` 通过才重启。
5. **卸载 sing-box**：清理核心、服务与运行配置，保留管理命令 `sbv`。
6. **启动 sing-box**。
7. **停止 sing-box**。
8. **重启 sing-box**。
9. **运行状态摘要**。

13. **系统设置**：BBR，以及入站监听栈和出站/DNS 策略。

原“实例与状态”分组已合并到现有协议入口：菜单 1 安装、菜单 2 管理、菜单 3 移除，主菜单不再重复列出每种协议。协议安装主列表按编号 1–14 排列，统一显示协议名称；VLESS 的两种形式在子菜单中选择。主列表留空仍选择全部可用协议（包含两种 VLESS），子菜单留空默认选择 VLESS + REALITY，输入 0 取消本次选择。协议/Agent ID 和已有配置不变。

## 服务与卸载保护

菜单 6/7/8 与 `sbv service start|stop|restart --json --yes` 共用校验和事务屏障。启动/重启前检查配置，操作后确认最终状态；组件、实例或规则事务待恢复时先恢复，不直接重启。菜单仅显示操作结果。

卸载先确认服务停止，再清理有所有权证据的实例防火墙规则和运行文件。停止、禁用或规则清理失败时返回失败并保留运行文件；规则补偿无法确认时保留私有恢复日志，按错误提示人工检查。无标记及无关防火墙规则保留。卸载仍是已登记的交互操作，不声明完整事务回滚。

## 网络与分流

菜单 12 只管理 VPS 服务端：Block CN、WARP 与节点出口、AI/流媒体设置。流媒体与出口检测位于此菜单内。新安装默认原生出口、Block CN/WARP 关闭；安装只填写节点连接参数，不创建分流策略或 WARP 账户文件。新节点继承已有策略，编辑保留原节点出口；安装、更新和删除节点不改变已有分流选择或 WARP 资料。

1. **Block CN**：菜单项后显示开启/关闭，选择后立即切换。默认关闭，开启后拒绝访问大陆域名与 IP（包括域名解析结果），优先于节点独立出口及 WARP。仅影响脚本管理的代理节点，不接管整机或手工入口。
2. **WARP 与节点出口**：菜单项后显示当前 WARP 状态及默认出口；可设置全局原生、选择性或全量 WARP，节点单独选择继承、原生或 WARP。高级设置兼容已有域名/IP/规则源，每次设置立即应用。默认原生不代表删除仍被节点或显式规则使用的 WARP；重新注册账户是需要明确确认的即时操作。
3. **AI / 流媒体**：菜单项后分别显示当前开关，选择对应预设后立即切换；只在全局选择性 WARP 模式下生效。
4. **流媒体与出口检测**：原生或已配置的 WARP 出口；检测不注册 WARP，不修改策略和节点。
5. **查看规则与恢复**：只读查看当前规则，或明确确认后恢复上次修改前的配置；旧 v1 策略可在此显式升级并清理已停用的受管规则。

已删除广告、局域网控制、客户端 LAN/CN 绕行和完整客户端配置导出。分享 URI/二维码、SubMan 和单节点连接材料保持。

旧 v1 策略只读兼容，节点安装和编辑保留其现有服务端规则。进入菜单只读取状态；存在旧策略时，菜单 5 行末和相关设置子页提示修改会清理旧版广告与私网限制。实际修改网络设置或明确选择旧策略清理时，才清理可证明由脚本生成的旧规则并保存精简 v2 策略。重复选择当前设置不应用、不重启，也不创建策略或触发旧策略转换。手工规则不按形状或 tag 前缀认领；无法无损保持内容/顺序时拒绝应用。

打开、查看、取消输入和返回不写运行状态、不注册账户、不重启；没有待应用草稿或返回时放弃修改的步骤。每次完整设置经私有候选和并发指纹检查后立即应用，并执行 `sing-box check`；原本活动的服务每次成功修改只重启一次，停止的服务保持停止。失败或中断回滚配置和原服务状态，不把失败设置留待下次应用；发现并发手工/ACME 变更时保留恢复材料，不自动覆盖。检测后重新读取当前策略再开始下一次修改。待恢复事务先通过菜单 12 恢复。WARP 注册只在明确网络操作时执行，云端注册无法由文件回滚撤销；保留收据以避免失败重试重复注册。完整设计与测试计划见[服务端网络 SPEC](https://github.com/KnowSky404/sing-box-vps/blob/main/docs/specs/server-only-network.zh-CN.md)。

“当前已安装协议”只列出活动协议。删除最后一个实例后留下的空实例库用于保留 revision，不算已安装；再次安装会复用实例事务创建，保留原 revision 和手工配置。合法空配置不进入残缺实例接管；真正缺少组件、状态不一致或校验失败的安装仍受原检查保护。

删除最后一个实例后，菜单 2 仍会显示保留的协议，并标注“暂无实例，可重新创建”；选择后可沿用保留的版本记录创建新实例。

Hysteria2 新增协议和创建实例默认提供 ACME 自动签发，也可选择已有手动证书。`server_name / SNI` 必填，填写与证书匹配的域名（如 `hy2.example.com`），不带 URL 前缀或路径。HTTP-01 需要域名解析到 VPS 且公网 TCP 80 可用于验证和续期；Cloudflare DNS-01 需要 DNS 编辑权限，无需开放 TCP 80，邮箱可留空。手动模式填写证书与私钥的本机绝对路径，自签名证书选择“信任此证书”。新建实例默认监听单个 `::`，接受 IPv4/IPv6 连接；不要在同端口另加 `0.0.0.0` 监听。修改时留空保留原地址，首次安装的 legacy 配置仍按全局入站模式监听。HY2 服务端口需要允许 UDP，带宽、混淆与伪装网站均为可选项。

当脚本发现二进制、service、配置或协议状态层不完整时，会进入接管/修复流程，而不是把残缺实例直接当作全新安装覆盖。

## 长耗时操作与配置共存

实例变更会显示校验、备份、配置发布、资源同步及服务检查阶段；耗时操作每 5 秒显示已等待时间，完成或失败会显示结果。ACME 的域名验证和证书签发可能需要较长时间。进度写入 stderr，Agent stdout 仍保留 JSON，进度信息不包含 Token、命令参数或配置内容。公网 IP 探测有连接及总时限。

脚本可以与手工配置共存。实例事务按原实例的 tag 更新入口，其他入口、出站、DNS、路由及顶层设置保留；手工组件不会仅因未登记到高级组件状态而被拒绝。完整候选仍需通过依赖图、监听资源和 `sing-box check`，已有协议索引时，Mixed/SOCKS/HTTP 按具体实例 tag 判断归属，同协议的未登记自定义 tag 也保留为手工配置；协议计数、状态校验及重建均排除这些手工入口，不隐式导入协议状态；默认保留 tag、已登记但状态缺失的入口仍执行完整性检查。未知入口类型或无法表示的同协议配置仍会停止操作并保留现场。

高级组件新增时按配置命名空间检查 tag：入口/出口/Endpoint 共用组件命名空间，HTTP Client、证书提供者、Service、网络命名空间和规则集各自独立；跨命名空间同名不会接管已有对象，同一命名空间的手工对象仍受保护。

防火墙同步只引用已登记协议/实例和启用的高级组件，不替手工入口、Endpoint 或 Service 放行端口。存在手工监听时，旧菜单也使用按地址及传输区分的防火墙事务，避免同端口不同地址之间的宽泛放行；现有手工防火墙策略不被接管。

全局重建在 `/root/.sing-box-vps/runtime/managed-config.generated.json` 保存仅含脚本生成内容的私有基线（权限 600），将上一生成基线、当前配置和新生成内容合并。手工添加的对象和设置保留，基线中的受管对象可更新或删除；同一受管值同时被手工及脚本改成不同内容时报告归属冲突，不覆盖。旧安装首次生成按匹配的 tag 建立基线；手工删除的路由规则保持删除，省略的默认出口按现场首个出站保留其实际语义；legacy 删除操作先记录删除前的基线。legacy 整体移除若可能删除共享配置中的手工扩展，会取消并提示使用实例事务或先迁移扩展。不要手工编辑或删除基线文件，配置和基线均属于备份与回滚范围。

首次建立基线时，若现场受管节点的监听地址、端口、认证用户、密码、UUID、密钥、出口目标、TLS/传输安全选项或 ShadowTLS 严格模式/SNI 策略与状态文件不一致，会拒绝生成并保留现场配置，避免扩大监听或恢复已经撤销的凭据；可选显示名称及兼容默认值的补齐不会视为凭据变化。请先核对并通过接管/状态重建同步现场设置，再执行管理变更。旧安装修改 Warp、协议栈或新增协议前会先在事务中记录原生成基线，使明确要求的全局变更生效，并保留手工扩展；首次生成不会把尚未生成的字段误判为手工删除。

## 修改 SubMan 连接

主菜单 **11 → 3「设置或修改 SubMan 连接」** 可以重新设置部署地址、API Token、同步身份前缀和目标 Workspace Gist ID。部署地址可以是站点根地址，也兼容粘贴以 `/api` 或 `/api/nodes` 结尾的地址；脚本会规范化，避免重复拼接 API 路径。地址不接受账号、查询参数或 URL 片段。

地址未变时留空保留已有值，Token 隐藏输入。更换部署地址必须重新填写 Token 和目标 Gist ID，不会把保存的旧 Token 发给新地址。保存前只读请求目标，验证鉴权、Workspace 身份及 revision 等元数据；校验失败或输入中断时保留原设置。成功后原设置备份为 `subman.env.bak`，新旧文件均为权限 600。保存设置不推送或删除节点；随后可通过 **11 → 2** 同步。

同步身份前缀（保存字段仍为 `SUBMAN_NODE_PREFIX`）参与 `externalKey`，修改它会创建新的节点身份。切换地址、Workspace 或前缀不会删除原目标中的节点；需要清理时在原目标明确操作。目标校验、本地 API mock 和真实节点同步是独立验证。

## 实例名称与主机显示标签

主菜单 **11 → 4「设置新实例的主机显示标签」** 只设置后续新建实例的默认名称，不修改已有名称、不重启服务，也不推送 SubMan。默认名采用“主机标签-规范协议 ID-序号”，保存的实例名称作为分享和 SubMan 候选名称的基础；多用户、带宽和地址族按统一规则追加后缀。此标签与同步身份前缀独立。已有实例名称仍通过菜单 2 的对应实例管理修改；完整规则见 [实例与节点命名](https://github.com/KnowSky404/sing-box-vps/wiki/Node-Naming.zh-CN)（[English](https://github.com/KnowSky404/sing-box-vps/wiki/Node-Naming)）。

### 流媒体与出口检测

菜单 `12 → 4` 保留本机直出与 WARP 检测。WARP 检测复用正式 sing-box
已有的认证 SOCKS/HTTP/Mixed 入口，经 loopback 转发；不启动第二个 sing-box 运行实例、
不读取或复制保存的 WARP 私钥、不改正式配置和路由，也不注册账户。

必须能确认正式服务已加载当前配置，并证明所选入口所有允许通过的流量固定
走 `warp-ep`。全局默认 WARP 或入口无条件 WARP 路由可以满足条件；此前可能
命中的 DIRECT、条件分流、selector 或未知路由动作均拒绝。然后通过该入口访问
HTTPS Cloudflare trace，只有 `warp=on/plus` 才运行后端。每次 curl 检查服务 PID
和配置摘要；变化后拒绝请求，最终结果标记无效。`NO_PROXY` 不会绕过代理。

仅有 VLESS/Hysteria2、无认证入口、只有选择性 WARP 或无法证明出口时，会明确
拒绝。检测不自动创建入口或修改出口策略；如需新增专用认证入口，应单独批准
配置变更。已有 Block CN 拒绝仍有效。检测仍是交互操作，外部后端没有稳定的
结构化结果，不能用模拟输入冒充 Agent 接口。

每次检测使用独立的私有目录和进程组；完成、失败、INT/TERM/HUP、父进程退出
或达到 15 分钟上限时清理后代进程和敏感临时文件。不会按进程名杀其他实例，
也没有检测用临时监听端口。代理认证只写入私有 curl 配置，不进入参数或输出。
SIGKILL/主机掉电无法执行被杀进程的 trap；独立监护处理父进程退出，整机掉电
或整个进程组被强杀后的磁盘残留仍须检查。
