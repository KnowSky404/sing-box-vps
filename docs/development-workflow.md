# 开发工作流

本流程适用于所有功能迭代和 Bug 修复。项目规约以 [AGENTS.md](../AGENTS.md) 为准；纯文档等其他改动也可使用相同流程。

1. **准备**：检查当前工作区、已有 worktree 和分支，保留其他工作。获取远程默认分支的最新状态，从该基线为本次任务创建独立分支和 worktree；不要在默认分支直接开发或推送。
2. **实现与验证**：在任务 worktree 中完成修改，按变更范围执行项目要求的测试。涉及安装器、卸载器、配置、工具或验证框架时遵守 [AGENTS.md](../AGENTS.md) 第 4 节的验证要求；命中远程规则时执行真实远程验证。记录通过、失败和未执行的检查及原因。
3. **提交与本地审查**：只提交本次任务相关内容，使用原子的 Conventional Commits。每次原子提交后立即运行 `/review`；如果当前环境没有该入口，审查对应提交的实际差异并记录这是等效审查。先修复审查发现的问题，再继续。脚本版本和 README 版本按项目规约同步。
4. **PR 与审查**：推送任务分支，创建面向默认分支的 PR，说明变更和验证结果。检查当前 PR head 的检查、审查记录、审查线程和合并状态。若 Codex 机器人或其他审查已触发或仍在排队、运行，等待其完成并处理意见；失败、取消或无法确认的审查需要排查并如实报告，不能视为通过。没有触发机器人审查时，核实实际状态并记录，不得把空的检查列表当作机器人已审查。
5. **更新与合并**：解决必要的审查意见和检查失败；如果产生新提交，重新验证受影响内容，确认最新 head 的审查和检查已完成，必要时重新触发审查。仅在门禁满足后使用 GitHub 的 rebase 合并；不得以 merge commit 或 squash 代替。若默认分支变化造成冲突或要求更新，先安全解决，再重新验证和确认审查。
6. **核对与清理**：确认 PR 已合并且远程默认分支包含合并结果，再删除远程任务分支。检查任务 worktree 的未提交、未跟踪和需要保留的产物；确认安全后移除 worktree 和本地任务分支。不要删除其他工作区或用户数据，清理失败时报告剩余内容。

本地提交审查、PR 机器人审查、测试和实际部署是不同的证据；其中某项未执行或未完成时，不能用其他项代替。若权限、检查或审查阻塞合并，保留 PR 和工作区并说明阻塞原因。
